# 第 1 阶段软件验证记录

日期：2026 年 10 月 17 日。范围：音乐文件 → 音频时间轴 → 软件拍掌事件 → 拍手声混音 → 最近目标判定 → Arcade 画面。未接入手套，未测量真实按键或接触到出声的延迟。

## 环境与参数

| 项目 | 本次条件 |
| --- | --- |
| 电脑／系统 | Apple Silicon MacBook Pro，arm64，macOS 26.5.1 |
| Python | 3.14.7，本地 `.venv` |
| 依赖 | Arcade 3.3.3、pyglet 2.1.19、numpy 2.5.4、sounddevice 0.5.6、soundfile 0.13.1 |
| 输出 | MacBook Pro Speakers，PortAudio，48,000 Hz，立体声 |
| 音乐 | 本地 `Rhythm hot pot vocal1001.mp3`；解码后 154.896 秒 |
| 节奏 | 四分音符 = 90；首拍 4.000 秒；全局偏移与输入补偿均为 0 |
| 练习谱面 | 4/4；每小节 `[4, 8, 8, 4, 4]`；全曲 284 个目标 |
| 判定 | 最近目标，对称 ±100 毫秒，包含端点；重复输入不消耗其他目标 |
| 启动与轮次 | 首拍拍手仅触发；`lead_in_bars = 1`，预备一小节后正式打一小节 |
| 音频／窗口 | 默认块大小 128；预载生成拍手声；1280 × 800 逻辑尺寸，Retina 屏幕 |

4/4、首拍拍手启动、每轮正式一个小节与拍手后才出现下落条已确认；按用户最新要求试用“启动后预备一小节”。循环模板、容差和重复处理是首版练习设置，未作为正式演出规则确认。音乐与正式节奏是否一致仍需人工核对。

## 配置与逻辑验证

```sh
.venv/bin/python beatgame.py --check
.venv/bin/python -m unittest discover -v
.venv/bin/python -m pip check
```

结果：配置与音乐解码通过，生成 284 个候选目标；69 项测试通过；依赖关系检查通过。每轮仅使用预备后正式小节的目标。测试覆盖：

- 四分／八分混合落点、不同小节首拍拍手触发、启动拍手不计分、预备一小节后首目标才计分、其他拍上拍手不启动、仅结算正式一个小节、最近目标、中点、窗口端点、重复和漏拍。另保留立即开始模式的测试。
- 正负全局偏移、输入补偿方向、持续早晚输入不移动后续目标。
- 输出 DAC 时间锚点、未输出缓冲、欠载间隙、音乐结束后的输入补偿余量。
- 音乐与拍手声混音、旧轮次隔离、暂停／继续、重来、配置无效时保留运行对象。
- 软件事件到音效、判定与日志的控制器链路，以及画面更新停顿后使用已知输入时间戳的行为。

音频逻辑测试使用模拟回调时钟，不用于测量声卡或操作系统延迟。

## 实际窗口验证

```sh
.venv/bin/python beatgame.py --demo-seconds 10 --screenshot tmp/phase1-arcade-result.png
```

实际打开 Arcade 窗口并播放音乐。自动输入在目标时间已知的条件下，4.000 秒注入一次启动拍手，正式小节从 6.667 秒开始、9.333 秒结束，再注入该小节的 5 次正式拍掌；10 秒得到 **5 次命中、0 次漏拍、0 次音频欠载**，启动拍手未计分，后续小节没有自动启动。这验证软件链路，不代表人手按键或手套可以零误差跟拍。

画面检查：五条谱线位于下落区域上方；固定音高展示四分／八分时值，两个八分音符以符杠连接；下落目标统一为短横线，到判定线时对应一次拍掌，不编码持续接触时长。已检查实际 Retina framebuffer 的完整布局。

另用实际原生 GL 窗口、模拟音乐位置检查绘制调用：等待启动时为 0 条下落短线；在第二小节首拍拍手触发后，成绩仍为 0，正式入口在一小节后，画面显示预备拍数与正式目标预览；正式入口处只绘制该小节 5 条短线；正式小节结束后为 0 条。窗口缩放与按键去重也通过原生窗口检查。

## 软件排程延迟观察

在上述电脑与输出设备上分别设置块大小 64、128、256、0（由设备选择）。每组触发 100 次，软件请求间隔约 13 毫秒；音乐及音效音量均设为 0，运行实际输出流。记录 `perf_counter()` 入队时间与回调中 `outputBufferDacTime` 映射到主机时钟后的差值，并单独记录 `stream.latency`。欠载数取 PortAudio 回调状态。

| 块大小 | 设备报告输出延迟 ms | 排程到计划 DAC 输出 P50 ms | P95 ms | 最大 ms | 欠载 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 | 17.96 | 4.26 | 4.81 | 4.89 | 0 |
| 128 | 19.29 | 6.37 | 7.49 | 7.57 | 0 |
| 256 | 21.96 | 9.52 | 12.36 | 12.83 | 0 |
| 0 | 17.96 | 4.29 | 4.87 | 4.89 | 0 |

10 秒 Arcade 单小节验证在默认 128 块下，6 次输入的对应软件估计为 P50 6.1 ms、P95 6.6 ms、最大 6.7 ms；样本较少，另列上表 100 次观察供比较。

两种数值来自不同 API 定义，不能相加，也不能用其中一个替代另一个。计划 DAC 时间由驱动报告，本次没有通过麦克风、回环或示波器验证其物理输出时刻；未计入真实输入采集、事件分发、正式声卡、音箱／耳返和空气传播。**这些结果不是接触到演员耳朵的延迟实测，也不构成演出延迟保证。** 当前保留 128 默认值，正式设备到位后重新比较稳定性与延迟。
